# ЗАДАНИЕ

Разработай одностраничное веб-приложение **Rhythmic Polygon** на чистом **HTML + CSS + JavaScript**.

Приложение должно позволять конструировать барабанные ритмы как систему **вложенных вращающихся неправильных многоугольников** и экспортировать полученный ритм в код **Strudel**.

Главная концепция:

> **Вершины многоугольника = музыкальные события.**
> **Длины сторон = временные интервалы между событиями.**
> **Радиус = инструмент/слой.**
> **Вращение = фазовое движение относительно master clock.**
> **Размер/интенсивность вершины = velocity/gain.**

Не делай обычный step sequencer с 16 кнопками. Геометрия должна быть основным способом создания ритма.

---

# 1. Технологические ограничения

Использовать:

* HTML5
* CSS3
* vanilla JavaScript ES6+

Не использовать framework без необходимости.

Предпочтительно не использовать build system.

Приложение должно запускаться локально простым открытием `index.html` либо через элементарный HTTP server.

Для визуализации использовать:

* SVG, либо
* Canvas 2D.

Предпочтительно SVG, если это упростит интерактивное редактирование вершин.

Архитектура должна быть модульной.

---

# 2. Главная задача

Пользователь должен иметь возможность:

1. выбрать основной размер;
2. выбрать количество инструментов от 1 до 5;
3. для каждого инструмента создать многоугольник;
4. задать количество вершин;
5. задать соотношение длин сторон;
6. задать фазу;
7. задать velocity каждой вершины;
8. задать скорость вращения;
9. запустить визуальное воспроизведение;
10. видеть, как многоугольники вращаются и взаимодействуют;
11. получить эквивалентный ритм в виде Strudel-кода.

---

# 3. Модель времени

Создать единый `MasterClock`.

Пример:

```js
{
  beats: 4,
  subdivision: 16,
  bpm: 120
}
```

Поддержать:

```text
beats:       1–16
subdivision: 1–64
BPM:         20–300
```

Все инструменты должны использовать один master timeline.

Важно:

**Не привязывать каждый инструмент к отдельному локальному 16-step grid.**

У инструментов могут быть дробные позиции событий.

---

# 4. Ритмический многоугольник

Каждый инструмент описывается массивом ratios.

Например:

```js
[3, 3, 2, 4]
```

означает четыре события и четыре временных интервала между ними.

Это НЕ обычный равномерный четырёхугольник.

События располагаются следующим образом:

```text
position[0] = 0

position[1] = 3 / total

position[2] = (3 + 3) / total

position[3] = (3 + 3 + 2) / total
```

где:

```js
total = ratios.reduce((a, b) => a + b, 0)
```

После этого полученные позиции масштабируются на длину master cycle.

---

# 5. Пример

Для:

```js
ratios = [3, 3, 2, 4]
```

получаем:

```text
total = 12

events:
0
3/12
6/12
8/12
```

Последняя сторона:

```text
4/12
```

замыкает цикл.

Таким образом пользователь задаёт **ритмическую форму**, а не просто количество ударов.

---

# 6. Неправильные многоугольники

Обязательно поддержать произвольные ratios:

```text
[1,1,1,1]
[3,3,2,4]
[5,2,3,2]
[1,2,1,3,1,2,2]
[2,3,2,3,2]
```

Не предполагать равномерность.

---

# 7. Инструменты

Максимум 5 инструментов.

Предустановки:

```text
Kick      → bd
Snare     → sd
Closed HH → hh
Open HH   → oh
Perc      → rim
```

Пользователь должен иметь возможность изменить имя и Strudel sample.

Каждый инструмент имеет:

```js
{
  id,
  name,
  sample,
  ratios,
  phase,
  rotation,
  gain,
  radius,
  color,
  muted
}
```

---

# 8. Визуальная модель

Показывать все инструменты как концентрические многоугольники.

Например:

```text
           HH polygon
      ┌─────────────────┐

         Perc polygon
        ┌───────────┐

          Snare
         ┌─────┐

          Kick
           ┌─┐
```

Каждый слой должен иметь собственный:

* цвет;
* радиус;
* толщину линии;
* размер вершин.

Master clock отображать как внешнюю окружность или сетку.

---

# 9. Вращение

Каждый polygon должен вращаться независимо.

Параметры:

```js
phase
rotationSpeed
direction
```

Например:

```text
Kick   = 1
Snare  = 1
Hat    = 5/4
Perc   = 7/4
```

Это должно создавать фазовое расхождение.

Важно:

**Не менять положение самих событий случайным образом при обычном вращении.**

Вращение должно быть детерминированным изменением фазы.

---

# 10. Фаза

Поддержать:

```text
0–360°
```

Пользователь должен менять фазу:

* slider;
* drag на canvas/SVG.

При изменении фазы весь polygon должен визуально поворачиваться.

---

# 11. Velocity / Gain

Каждая вершина имеет velocity:

```text
0.0–1.0
```

Пример:

```js
gain: [
  1.0,
  0.4,
  0.7,
  0.5
]
```

Визуально:

* сильный удар = большая вершина;
* слабый = маленькая вершина.

Пользователь должен иметь возможность изменять velocity каждой вершины.

При экспорте:

```js
.gain("1 0.4 0.7 0.5")
```

# 12. Интерактивное редактирование

Обязательные действия:

### Drag вершины

Меняет timing соответствующего события.

### Drag по радиусу

Меняет визуальный radius.

### Click по вершине

Включает/выключает событие.

### Shift + drag вершины

Меняет velocity.

### Drag polygon

Меняет phase.

Интерфейс должен сразу обновлять Strudel output.

Для 4/4 + 16 subdivisions:

```text
| . . . . | . . . . | . . . . | . . . . |
```

# 14. Quantize

Добавить:

```text
Quantize: OFF / ON
```

Если OFF:

сохранять точную дробную позицию.

Если ON:

округлять к выбранной сетке:

```text
1/4
1/8
1/16
1/32
```

Quantization не должна изменять ratios самого polygon — она применяется только при преобразовании его событий в дискретное представление.

# 15. Engines

Реализовать систему engines.

## Engine: Static

Polygon не вращается.

```text
rotationSpeed = 0
```

## Engine: Rotation

Polygon равномерно вращается.

```text
phase += rotationSpeed * deltaTime
```

## Engine: Phase Drift

Фаза постепенно смещается.

```text
phase += drift * deltaTime
```

## Engine: Mutation

Периодически изменять ratios.

Пример:

```text
[3,3,2,4]

→ [3,2,3,4]

→ [2,3,3,4]
```

По умолчанию сохранять сумму ratios.

## Engine: Controlled Random

Добавить:

```text
seed
mutation probability
mutation amount
cycle length
```

Одинаковый seed должен давать одинаковый результат.

---

# 16. Генеративность

Генеративный режим не должен превращать ритм в хаотичный random.

Использовать:

* deterministic seed;
* ограниченную mutation;
* фазовый drift;
* сохранение общей длины цикла;
* сохранение количества вершин;
* ограничение максимального изменения ratio.

Цель:

> создавать контролируемое развитие ритма, а не случайный барабанный шум.

# 21. Strudel Exporter

Главный output приложения — Strudel.

Пример:

```js
stack(
  s("bd ~ ~ bd"),
  s("~ sd ~ ~"),
  s("hh ~ hh ~ hh"),
  s("rim ~ ~ rim")
)
```

Добавлять gain:

```js
stack(
  s("bd ~ ~ bd")
    .gain("1 0 0.7 0.5"),

  s("~ sd ~ ~")
    .gain("0 0.8 0 0")
)
```

---

# 22. Оптимизация Strudel

Exporter должен по возможности сокращать очевидные повторения.

Например:

```js
hh hh hh hh
```

превращать в:

```js
hh*4
```

Но **не жертвовать точностью ради краткости**.

Если ритм нерегулярный:

```text
hh ~ hh ~ ~ hh ~
```

оставлять явный pattern.

---

# 23. Экспорт дробных позиций

Критически важно:

**Exporter не должен молча округлять события, которые находятся между grid positions.**

Если конкретный Strudel representation не может выразить положение напрямую, использовать подход Strudel, сохраняющий необходимую временную структуру.

При невозможности точного представления вывести предупреждение:

```text
Some events require fractional timing.
Quantize or use explicit subdivision.
```

# 29. Математическая модель

Для каждого polygon:

```js
total = sum(ratios)
```

Позиция вершины:

```js
position[0] = 0

position[i] =
  sum(ratios.slice(0, i)) / total
```

Затем:

```js
absoluteTime =
  position[i] * masterCycle
```

Фаза:

```js
absoluteTime += phase
```

После нормализации:

```js
absoluteTime %= masterCycle
```

---

# 30. Генеративная модель

Mutation должна работать с ratios.

Пример:

```text
[3,3,2,4]
```

может стать:

```text
[3,2,3,4]
```

но не:

```text
[0.01, 100, 0.02, 1]
```

Ввести:

```text
minRatio
maxRatio
maxMutation
```

и сохранять:

```text
sum(ratios)
```

если пользователь не включил режим свободной длины цикла.

# 31. Режимы длины цикла

Добавить два режима:

### LOCKED

Все polygon нормализуются к длине master cycle.

```text
[3,3,2,4]
```

и

```text
[5,2,3,2]
```

могут иметь разные ratios, но занимают один master cycle.

### FREE

Каждый polygon имеет собственную длину цикла.

Это позволяет создавать настоящие phase-polyrhythms.

# 35. Ключевой принцип продукта

Не превращать приложение в ещё один drum sequencer.

Основной UX должен ощущаться как:

> **«Я конструирую геометрию времени».**

Пользователь должен видеть, как несколько ритмических объектов:

* вращаются;
* пересекают общие фазы;
* расходятся;
* снова совпадают;
* меняют внутреннюю геометрию;
* создают сложный groove.

Strudel является **выходным языком**, а не основной моделью данных.

Внутри приложение должно работать с собственной геометрической моделью ритма.


```text

      ↓

```

После этого переходить к генеративным engines.
